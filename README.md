# 地球仪 Globe

摄像头手势控制 / 鼠标控制 · p5.js 项目

## 怎么运行

1. VS Code 里右键 `index.html` → **Open with Live Server**
2. 浏览器打开后点 **允许** 使用摄像头（不点也能用鼠标操作）

## 两种控制方式（会自动切换）

**1. 手部识别模式（默认，推荐）**

用的是 MediaPipe Hands，只启用单手识别并锁定第一次识别到的手：

| 动作 | 效果 |
|---|---|
| 手掌左右 / 上下移动 | 地球跟着你的手掌转（完全跟手，不会抖） |
| 单手五指收拢 / 张开 | 缩小 / 放大；张开一次会继续补完缩放，手掌平移时暂停以避免误触 |
| **单手比耶 ✌️ 并保持约 0.4 秒** | **手动触发一次流星雨**（自然流星雨仍然保持极其稀有） |
| **拇指与食指连续捏合两下** | 进入“观察者模式”并短暂显示提示；每次进入时首个城市固定从上海 / 纽约中选离当前视角更近的一座，避免镜头乱飞；之后按手掌拨动方向的反向选择最近重点城市，符合转动地球仪的手感；屏幕下方以大号中文 + 英文上下排列显示选中城市；五根指尖捏合后轻晃两次即可退出，地球核心区粒子自动减弱 |
| **鼠标点击城市光点或名称** | 聚焦任意可见城市；单击空白处返回 |
| **只识别第一只手** | 识别到第一只手后会锁定左右手标签，另一只手进入画面也不会参与控制 |
| **手甩一下后离开画面** | **地球继续靠惯性转，慢慢停下**（像真的拨了一下地球仪） |

**2. 画面运动模式（兜底）**

如果手部识别没启动，或者画面里没检测到手，会自动退回「比较前后两帧画面」的方式：
手在镜头前挥动 → 地球跟着转。稳定性差一些，但不会完全不能用。

左上角的状态行会告诉你现在是哪种模式、检测到几只手、已经处理了多少帧。

## 会看到什么

一颗由 3000 多个光点组成的深蓝地球，缓慢自转：

- **陆地**：密、亮、点小（约 8600 个点，`DOT_STEP = 1.25°`），海岸线跟着真实贴图走
- **海洋**：疏、暗、点更小（约 1140 个点，`SEA_STEP = 5°`）
- 正面亮、背面暗，所以球有立体感
- 上面标着 17 个城市和 11 个国家/地区；放大后，靠屏幕中央的城市名会平滑变亮、变大，转出中央后再淡回普通亮度
- **三颗人造卫星**在各自的轨道上绕着地球转：轨道是点状的（和经纬网同一种语言），
  卫星是黄铜色的点 + 一段尾迹；**被地球挡住的段落会自动消失，跑进地球阴影里会变暗**
- **两颗绕月人造卫星**沿一近一远、倾角不同的点阵轨道绕月飞行，月球会自然遮挡轨道和卫星的后半段
- **一座近地轨道空间站**沿 51.6° 倾斜点阵轨道运行：中央舱体、横向桁架和两片太阳翼会随受光变化，缺少长尾迹以区别于普通卫星
- 太阳是真正的光源：晨昏线、球缘高光、卫星的明暗都由它决定；地球受光侧还有一层极淡的暖白边缘光，沿弧长渐入渐出
- **全球主干航线与航班**：**放大到 1.35× 以上才渐渐出现**（1.8× 完全显现）。
  198 条真实主干航线用点状大圆弧表示（和经纬网/卫星轨道同一种画法），其中香港 30 条、新加坡 30 条，
  上面有 1~2 架航班在飞；飞机后方保留一段与飞机同色的 9~15 段渐隐尾迹，不改变底下航线颜色；美国部分补充了凤凰城、拉斯维加斯、波特兰、明尼阿波利斯、底特律、奥兰多、盐湖城、檀香山、安克雷奇和费城的航线。
  默认视角完全看不到，所以画面不会变"忙"；按 **`f`** 可以强制显示，方便截图。
- **月亮**：屏幕暗面（右下）的一颗**灰色像素粒子球**，停留不动、只做 ±3° / 120 秒的极缓慢摆动。
  - 月面由约 3000 个球面采样点组成（朝向镜头时约 1500 个），用和地球海陆点阵相同的 `fillRect` 像素块逐点绘制
  - 每个点都按它与太阳的夹角单独受光，再分成 6 档冷灰批量上色；亮侧、晨昏线和暗侧由点阵自然形成，不再画整块月盘、椭圆终止线或轮廓
  - 12 个真实月海坐标只用来让落在范围内的点变暗、略缩，形成点阵里的暗斑，不贴任何渐变图片
  - 月相读数 = `(1 + L.z) / 2`，现在 73%（凸月）
- **极光**：夜面高纬度的青白色光带（南北两极各一条），随"太阳风"缓慢起伏（20~40 秒一个周期），
  白天一侧完全看不到。它在所有倍率都可见，是夜景的一部分。
- **背景星空**：大部分星点保持静止，只有少量星点以 12~24 秒周期轻微起伏；天空里还有极淡的星尘缓慢漂移，
  以及稀有的分层点阵流星：首颗约等待 5~9 秒，之后约每 20~34 秒出现一次；头部沿随机微曲线滑动，大小、曲率和距离都会变化；短流星之外，普通流星约 17% 为大半屏长轨迹、5% 为接近整屏的超长轨迹，流星雨中这两档分别提高到 32% 和 18%，同时最多两颗。
  此外约每 15~30 分钟会出现一次持续 16~20 秒的双层流星雨事件；发生时屏幕下方显示 2 秒大号“流星雨 / METEOR SHOWER”，来源方向出现极淡冷蓝辐射光；密集阶段约每 0.06~0.15 秒补一颗、同时最多 26 颗（近层 12 / 远层 16），形成有纵深的连续流星幕。
  比耶手动触发时，开场 2 秒约 55% 的流星会变成黄铜金色并带暖色头部光晕，随后金色比例降到约 28%；自然流星雨和普通流星始终是冷蓝白。

### 航线 / 极光 怎么调

| 想改什么 | 改哪里 |
|---|---|
| 加减航线 | `sketch.js` 里的 `ROUTES`（`["北京", "上海"]` 这种，两端必须是 `CITIES` 里已有的城市名） |
| 什么时候出现 | `drawFlights()` 里的 `const vis = constrain((zoom - 1.35) / 0.45, 0, 1);` |
| 虚线疏密 | 同函数里的 `const per = constrain(Math.round(dist / 4), 1, 16);`（`4` = 每 4 像素一个点） |
| 航线亮度 | 顶部的 `ROUTE_ALPHA_DAY / ROUTE_ALPHA_MID / ROUTE_ALPHA_NIGHT`（现在 `0.20 / 0.13 / 0.08`） |
| 航班速度 | `buildRoutes()` 里的 `speed: 1 / (25 + (i * 7) % 36)`（跑完全程 25~60 秒） |
| 航班尾迹 | `drawFlights()` 里的 `tailPoints`、`0.0095` 点距和 `0.62` 基础亮度 |
| 极光亮度 | `drawAurora()` 里的 `const a = night * pulse * 0.34;` |
| 月亮位置 | 顶部的 `MOON_DIR`（`{x,y,z}` 方向；现在是右下暗面） |
| 月亮大小 | `MOON_R`（地球半径的倍数，真实比例 0.27） |
| 月面点阵密度 | `MOON_STEP`（现在 3.7°；越小点越密、越接近实心） |
| 月面点大小 | `MOON_DOT`（现在 1.55；会随月亮屏幕半径轻微缩放） |
| 月面灰度 | `MOON_BANDS`（6 档冷灰；最后一档是受光面高光） |
| 月海形状 | `MOON_MARIA` 数组（每项 `lat/lon/rx/ry`，控制哪些点变暗） |
| 月亮摆动 | `MOON_SWAY`（幅度，度）和 `MOON_SWAY_PERIOD`（周期，秒） |
| 月亮离地距离 | `MOON_DIST`（地球半径倍数，现在 2.0） |
| 绕月卫星轨道 | 顶部的 `MOON_ORBITS`（半径、倾角、相位和速度） |
| 近地空间站轨道 | 顶部的 `STATION_ORBIT`（半径、倾角、相位和速度） |
| 极光位置 | `buildAurora()` 里的 `66`（纬度）和 `7 * Math.cos(...)`（朝磁极的偏移） |
- **放大粒子吸积**：低倍率时约 4200 个冷蓝白粒子分散在整个屏幕中漂浮，并主动避开地球核心区，保证城市灯光和名称清晰；放大到 1.35× 后海岸点先附着，随后向内陆补点，2.15× 左右完全并入陆地点阵并保持增密，缩小时再缓慢脱离。
- **四项交互效果**：手掌掠过时全屏漂浮粒子主动让路；点击城市或名称会把城市平滑转到中央，并让所选城市灯点、名称和关联航线同步闪烁约 0.9 秒；闪烁峰值时航线过渡为城市灯点的暖黄色，之后保持聚焦增强；快速转动时卫星和航班尾迹拉长；空间站视觉过顶城市时，对应城市灯光和名称短暂脉冲。
- **夜面城市灯光**：地球背光的那半面，108 座城市变成暖色小光点（像从太空看地球夜景）。
  每座城市以不同相位轻微呼吸（约 8 秒一轮）；小城市和偏远城市的光点会略小、略暗，和洲际枢纽形成层次。
  受光面则是"仪器标注"风格（黄铜点 + 细环 + 名称），两种表现方式在晨昏线附近交叉淡入淡出。

### `SUN_DIST` 怎么选（可见半球里"白天 / 夜面"的比例）

太阳是**有限远的强光源**，不是无限远的平行光 —— 所以离得越近，照亮的范围越小，夜面越大：

| SUN_DIST | 白天 | 夜面 |
|---|---|---|
| 5.0（接近无限远，老样子） | 72% | 28% |
| 3.0 | 61% | 39% |
| **2.0（当前）** | **38%** | **62%** |
| 1.6 | 24% | 76% |
| 1.4 | 17% | 83% |

副作用：太阳越近，它在画面上也越靠近地球、越靠边；放大倍率超过 1.5 倍时它会移出画面（缩小回来就能看到）。

| 操作 | 效果 |
|---|---|
| 手在摄像头前左右移动 | 地球跟着左右转 |
| 手上下移动 | 地球上下翻 |
| 鼠标拖拽 | 转动（不依赖摄像头） |
| 滚轮 | 缩放 |
| `空格` | 暂停 / 恢复自转 |
| `[` / `]` | 左右灵敏度调低 / 调高（左上角显示当前值） |
| `v` | 上下手势方向反转 / 恢复 |
| `f` | 强制显示 / 隐藏航线（默认要放大到 1.35× 以上才出现；没放大时读数会写「放大后可见」） |
| `c` | 摄像头开关 |
| `d` | 调试视图（看它怎么判断动作） |
| `s` | 保存 PNG |
| `r` | 复位视角 |

## 能做到什么程度（实话说）

- **「手转地球」**：很稳，因为只需要判断「画面往哪个方向在动」，这个信号很干净
- **「五指缩放」**：用本地 MediaPipe 计算五根指尖的聚合度，五指收拢缩小、张开放大；
  手掌明显平移时会暂停缩放，降低左右滑动误触。手势模型不可用时，才退回摄像头运动范围判断。
- **「拇指食指双捏合」**：连续捏合两下进入看城市模式；左右或上下摆手会反向选择最近的一个 `KEY_CITIES` 重点城市，手掌回到静止后才能继续切换。鼠标拖拽和 `r` 可以直接退出；五根指尖聚拢后，在约 1.4 秒内左右或上下轻晃两次即可退出；持续全捏合仍作为备用方式。

## 代码结构

```
globe/
├── assets/mediapipe/  ← 手部识别库（23MB，本地文件，不用联网）
├── index.html      ← 页面 + 左上角说明文字
├── sketch.js       ← 全部逻辑（约 300 行，中文注释）
├── css/style.css
├── js/p5.min.js    ← p5.js（本地，离线可用）
└── assets/earth.jpg ← 地球贴图 2048×1024（判断哪里是陆地就靠它）
```

三块核心逻辑：

1. **`readLand()`** — 把贴图缩到 720×360 读像素，逐点判断「这里是不是陆地」，
   把陆地点转成球面坐标存起来（约 2100 个点）。判断规则：海水偏蓝（蓝比红高很多），
   陆地偏绿/棕/白；北极圈那片海冰不画，否则会变成一大块实心帽子。
2. **`project()`** — 把球面上的点按当前视角旋转，再投影到屏幕（近大远小）。
   正面亮、背面暗，所以点越多立体感越强。
   注意：它返回的是**同一个复用对象**（避免每帧创建上万个对象导致卡顿）。
   点用批量 `fillRect` 画（比 p5 的 `point()` 快得多），所以 8600 个点也不卡。
3. **`readGesture()`** — 每帧比较摄像头画面，算出运动中心往哪走（→ 转动）
   和运动范围有多大（→ 缩放）。

## 先改这几个参数（手部识别）

| 参数 | 现在 | 说明 |
|---|---|---|
| `HAND_FOLLOW_X` | **2.4** | **左右**灵敏度（运行中按 `]` 变灵敏、`[` 变迟钝，左上角显示当前值） |
| `HAND_FOLLOW_Y` | 1.0 | **上下**灵敏度 |
| `INVERT_Y` | **-1** | **上下方向**：`1` 正常、`-1` 反过来（运行中按 `v` 切换，左上角会显示） |
| `MOMENTUM` | 0.90 | 甩手后保留多少「劲」：`0.95` 保留更久、`0.8` 停得更快 |
| `GLIDE` | 0.965 | 惯性滑行的衰减：`0.98` 滑得更久、`0.94` 更快停 |
| `HAND_STILL_BASE / ZOOM / WAKE_MULT` | 0.0009 / 0.0028 / 1.7 | 放大静止观察时的抖动锁定；只过滤微动，不改变原有跟手灵敏度 |
| `HAND_VERTICAL_NOISE / RATIO / CONFIRM` | 0.18 / 0.34 / 2 | 横向转动时过滤上下抽动；浅斜向需连续两帧同方向才放行 |

代码里 `hands.setOptions()` 里还有两个：`modelComplexity`（改成 `0` 更快但略粗）、
`minDetectionConfidence`（调小更容易检测到手、但更容易误检）。

## 先改这几个参数（整体）

| 参数 | 现在 | 说明 |
|---|---|---|
| `DOT_STEP` | **0.9** | 陆地点密度：`0.7` 更实心（约 27000 点，会更吃性能）、`1.5` 更轻 |
| `LAND_DOT` | **2.5** | 陆地点大小：调到 `3.5` 就基本实心了 |
| `SEA_STEP` | 5.0 | 海洋点密度：`4` 更密、`8` 更疏（`8` 时海洋会很空） |
| `GLOBE_RATIO` | 0.34 | 地球占屏幕的比例 |
| `AUTO_SPIN` | 0.0012 | 自动自转速度，`0` 就不自转 |
| `FOLLOW` | 5.0 | **跟手程度**：手移动时地球转多少。觉得还不够就跟到 `8`，太夸张就降到 `3` |
| `SPREAD_LO / SPREAD_HI` | 0.15 / 0.80 | 缩放的手势范围，调这两个最容易改变捏合手感 |

## 手部识别的文件从哪来（可离线）

`assets/mediapipe/` 里是 `@mediapipe/hands@0.4.1675469240` 这个 npm 包的内容，
是从**阿里 npmmirror 镜像**下载的（`registry.npmmirror.com`），所以不需要代理、
也不依赖 Google 的服务器。模型（`.tflite`）和 WASM 都在本地，断网也能跑。

以后想升级版本：从 npmmirror 下载新的 tgz，解压后替换这个文件夹里的文件即可。

## 手势手感怎么调（最常用的四个）

想象你在用手拨一个真的地球仪：

- **手推着它转** → `FOLLOW`（默认 5.0）。这是灵敏度总开关
- **松手后它还自己滑一会儿** → `FLICK`（劲道）+ `GLIDE`（滑多久）
- **轻轻动一下就想有反应** → 把 `MOTION_MIN` 调小到 25
- **它太爱乱转** → `FOLLOW` 降到 3，`MOTION_MIN` 升到 55

## 手感调试：卡顿 / 抽动 / 没反应

手势识别最容易翻车的三件事，代码里已经分别处理：

| 症状 | 原因 | 已做的处理 | 想再调 |
|---|---|---|---|
| 画面自己抽动 | 摄像头噪点、光线变化被当成运动 | 邻域去噪（孤立点丢掉）+ 死区 + 速度平滑 | `MIN_MOTION` 调到 `25`，`VEL_SMOOTH` 调到 `0.75` |
| 手重新出现时猛跳 | 运动中心从「旧位置」跳到「新位置」 | 检测不到手时清空基准 | 无 |
| 有时完全没反应 | 触发门槛太高 / 光线太暗 | 门槛从 45 降到 35，检测精度提高 | `MOTION_MIN` 到 `25`，`MIN_MOTION` 到 `10` |
| 整幅画面都在变（开灯、逆光） | 曝光调整 | 检测到超过 40% 画面在变就忽略这一帧 | 无 |

> 调试技巧：按 `d` 打开调试视图，右下角会显示**运动点数**和**当前速度**。
> 手慢慢移动时，速度应该平滑地从一个值变到另一个值，而不是乱跳——看到乱跳就说明环境光或噪点在干扰。

## 想加城市 / 国家

改 `sketch.js` 里的 `places` 数组就行，格式：

```js
{ name: "柏林", lat: 52.52, lon: 13.40, type: "city" }
```

`type` 用 `"city"`（黄色实心点）或 `"country"`（青色圆圈）。经纬度上网一查就有。

## 出问题

- **一片黑，只有球轮廓** → 贴图没读到：确认 `assets/earth.jpg` 在，并且是用 Live Server 打开的
- **很卡** → `DOT_STEP` 改成 `4`
- **手势太灵敏 / 不灵敏** → 调 `FOLLOW`（跟手程度）和 `MOTION_MIN`（触发门槛）
